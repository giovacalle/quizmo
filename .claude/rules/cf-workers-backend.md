# Cloudflare Workers Backend Standards

Location: `src/lib/server/` and `src/routes/**/+server.ts` (all code running on the Worker edge).

Applies to: SvelteKit server hooks, +server routes, DB/KV/DO helpers, Durable Object classes, `scheduled()` handlers.

## Runtime Contract

The app runs on **Cloudflare Workers** via `@sveltejs/adapter-cloudflare`. No Node.js primitives:

- ❌ `fs`, `path`, `child_process`, `crypto` from `node:crypto`
- ❌ `process.env` — use `platform.env` (SvelteKit) or `env` (DO/cron)
- ❌ Node.js streams, long-lived timers that outlive a request

Bindings live on `platform.env` (SvelteKit load/action) or `env` inside DOs / `scheduled()`:

```typescript
// +page.server.ts — SvelteKit context
export const load = async ({ platform }) => {
	const db = platform!.env.QUIZMO_DB;
	const kv = platform!.env.QUIZMO_AUTH_KV;
};

// durable object — runtime context
export class QuizSession extends DurableObject<Env> {
	constructor(ctx: DurableObjectState, env: Env) {
		super(ctx, env);
	}
}
```

Types for `Env` are generated by `wrangler types` into `worker-configuration.d.ts`. Never hand-write the `Env` interface — it will drift.

## Bindings (project-specific)

| Binding          | Resource                     | Purpose                                                                                                    |
| ---------------- | ---------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `QUIZMO_DB`      | D1 `quizmo-db`               | Users, quizzes, questions, answers, quiz_sessions, participants                                            |
| `QUIZMO_AUTH_KV` | KV `quizmo-kv-auth`          | better-auth sessions, OTP codes, rate-limit counters (prefixes: `session:`, `otp:`, `rl:email:`, `rl:ip:`) |
| `QUIZMO_QUIZ_KV` | KV `quizmo-kv-quiz`          | Join-code cache `code:{CODE}` → `sessionId` (D1 is authority)                                              |
| `QUIZMO_SESSION` | Durable Object `QuizSession` | Live quiz session state; id via `idFromName(sessionId)`                                                    |

**Key prefix discipline is non-negotiable** — accidental cross-namespace key collision is a data leak.

## Error Handling (backend) — `AppError` + `throwAppError`

The equivalent of legacy's `throwAppError` for this stack. Location: `src/lib/server/errors.ts`.

```typescript
export type ErrorCode =
	| 'NOT_FOUND'
	| 'UNAUTHENTICATED'
	| 'FORBIDDEN'
	| 'INVALID_INPUT'
	| 'CONFLICT'
	| 'INTERNAL_ERROR';

export class AppError extends Error {
	constructor(
		public readonly code: ErrorCode,
		message: string
	) {
		super(message);
		this.name = 'AppError';
	}
}

export const throwAppError = (code: ErrorCode, message: string): never => {
	throw new AppError(code, message);
};

export const isAppError = (e: unknown): e is AppError => e instanceof AppError;

export const httpStatusFor = (code: ErrorCode): number =>
	({
		NOT_FOUND: 404,
		UNAUTHENTICATED: 401,
		FORBIDDEN: 403,
		INVALID_INPUT: 400,
		CONFLICT: 409,
		INTERNAL_ERROR: 500
	})[code];
```

### Usage pattern

```typescript
import { throwAppError } from '$lib/server/errors';

// ✅ GOOD
const quiz = await db.select().from(quizzes).where(eq(quizzes.id, id)).get();
if (!quiz) throwAppError('NOT_FOUND', 'Quiz not found');

if (quiz.ownerId !== locals.user.id)
	throwAppError('FORBIDDEN', "You don't have permission to edit this quiz");

// ❌ BAD — raw Error, no code
if (!quiz) throw new Error('Quiz not found');
```

### Style: single-line if + throw (no braces)

```typescript
// ✅ GOOD
if (!user) throwAppError('UNAUTHENTICATED', 'You must be logged in');

// ❌ BAD
if (!user) {
	throwAppError('UNAUTHENTICATED', 'You must be logged in');
}
```

### Standard error codes

| Code              | When                                         |
| ----------------- | -------------------------------------------- |
| `NOT_FOUND`       | Resource doesn't exist                       |
| `UNAUTHENTICATED` | No / invalid session                         |
| `FORBIDDEN`       | Authenticated, not authorized                |
| `INVALID_INPUT`   | Validation failed                            |
| `CONFLICT`        | Resource already exists / unique violation   |
| `INTERNAL_ERROR`  | Unexpected failure (DB, Resend, third-party) |

Mapping to HTTP happens centrally in `hooks.server.ts` via `handleError`. Never return raw exceptions to clients.

## Authentication pattern

Auth check must be the first thing in any protected handler. `locals.user` is populated by `hooks.server.ts`:

```typescript
// +page.server.ts
export const actions = {
	createQuiz: async ({ locals, request, platform }) => {
		if (!locals.user) throwAppError('UNAUTHENTICATED', 'Sign in required');

		const data = await request.formData();
		// ... validate via Valibot schema from $lib/server/db/validators
		// ... conditional insert via D1 for TOCTOU-free cap enforcement
	}
};
```

For DO methods that need caller identity, verify via participant token (HMAC) — never trust raw `participantId` from reconnecting clients.

## D1 + Drizzle

Schema is the **single source of truth**. `drizzle-valibot` derives insert/select schemas; hand-written refinements in `src/lib/server/db/validators.ts` layer on business rules.

```typescript
// src/lib/server/db/client.ts
import { drizzle } from 'drizzle-orm/d1';

import * as schema from './schema';

export const db = (d1: D1Database) => drizzle(d1, { schema });

// usage in +server.ts / +page.server.ts
const client = db(platform!.env.QUIZMO_DB);
const rows = await client.select().from(schema.quizzes).where(eq(schema.quizzes.ownerId, userId));
```

### Migration safety

- Generate with `bunx drizzle-kit generate`.
- **Human-read** the emitted SQL before `wrangler d1 migrations apply --remote`.
- Never apply migrations while `quiz_sessions.status = 'active'` exists (query first, halt if > 0).
- Dev + prod share the same D1 (`quizmo-db`) — demo-only decision, be explicit.

### TOCTOU-free cap enforcement

Race-safe counters use conditional insert:

```sql
INSERT INTO quizzes (id, owner_id, title, description, status, created_at, last_active_at)
SELECT ?, ?, ?, ?, 'draft', ?, ?
WHERE (SELECT COUNT(*) FROM quizzes WHERE owner_id = ? AND status = 'active') < 3
  AND (SELECT COUNT(*) FROM quizzes WHERE owner_id = ? AND status != 'archived') < 20;
```

Check `result.meta.changes` — if 0, the cap was exceeded. Follow with a count query to emit the right `AppError`.

### FK cascades

Defined in schema:

- `quizzes.owner_id → users.id ON DELETE CASCADE`
- `questions.quiz_id → quizzes.id ON DELETE CASCADE`
- `answers.question_id → questions.id ON DELETE CASCADE`
- `quiz_sessions.quiz_id → quizzes.id ON DELETE CASCADE`
- `participants.session_id → quiz_sessions.id ON DELETE CASCADE`

## Durable Objects — Storage Write-Through (MUST)

In-memory `Map`s inside a DO are **cache only**. `ctx.storage` is the source of truth. Every mutation follows:

1. Mutate in-memory.
2. `await ctx.storage.put(...)` the touched keys.
3. Only then broadcast to WebSockets or return from the method.

If a DO wakes from hibernation or eviction (including alarm fires on a cold instance), rehydrate from `ctx.storage` before acting. **Never** assume an empty in-memory state means "fresh instance" — an alarm on a cold DO is normal.

### Storage key layout (session)

- `meta` → `{ sessionId, sessionSecret, status, currentQuestionIdx, questionStartedAtMs }`
- `question:{idx}` → snapshot of the quiz question (loaded from D1 on start)
- `participant:{pid}` → `{ nickname, score, joinedAt }`
- `answer:{qIdx}:{pid}` → `{ choice, answeredAtMs }`

### Alarms + timers

Timer uses `ctx.storage.setAlarm(now + timeLimitSec * 1000)`. `alarm()` callback reads `meta`, transitions state, re-persists, then broadcasts. Never send `tick` messages from the server — clients compute `timeLeft` locally against `questionStartedAtMs`.

### WebSocket hibernation

Use `ctx.acceptWebSocket(server)` — NOT `server.accept()`. Message handling happens via `webSocketMessage(ws, msg)` / `webSocketClose(ws, code)`. The Worker that forwards the upgrade MUST pass the raw `Request` to the DO via `stub.fetch(request)` — never `new WebSocketPair()` inside the Worker, that breaks hibernation and makes every message cost a Worker invocation.

## KV patterns

### Rate limiting

```typescript
// src/lib/server/auth/rate-limit.ts
export async function bumpRateLimit(kv: KVNamespace, key: string, max: number) {
	const raw = await kv.get(key);
	const count = raw ? Number(raw) + 1 : 1;
	if (count > max) throwAppError('INVALID_INPUT', 'Too many requests');
	await kv.put(key, String(count), { expirationTtl: 3600 });
}
```

~1-minute race imprecision at boundaries is acceptable for anti-abuse.

### Join-code cache

D1 `quiz_sessions.code UNIQUE` is authority. KV `code:{CODE}` is a read-through cache with 1-hour TTL. Cache miss → query D1 → populate → return. Eviction is not a correctness issue.

## Cron Triggers

Nightly cleanup runs via `scheduled(event, env, ctx)` exported from the Worker entry — **NOT** an HTTP route. Cron Triggers invoke the handler directly; there is no spoofable request path. Do not build `cf-worker: 'cron'` header guards — they're fiction.

```typescript
// src/lib/server/cron/cleanup.ts
export async function runNightlyCleanup(env: Env) {
	// archive stale quizzes, reconcile stuck sessions, clear dead KV cache entries
}

// worker entry
export default {
	async fetch(request, env, ctx) {
		/* SvelteKit handler */
	},
	async scheduled(_event, env, ctx) {
		ctx.waitUntil(runNightlyCleanup(env));
	}
};
```

## Adapter quirk — named exports for DO + `scheduled`

`@sveltejs/adapter-cloudflare` only emits `export default { fetch }` on `.svelte-kit/cloudflare/_worker.js` — there's no hook to inject additional named exports. Cloudflare Workers requires **both** `QuizSession` (the DO class, referenced by `durable_objects.bindings` in `wrangler.jsonc`) and `scheduled` (for Cron Triggers) as named exports on the same entry module.

`scripts/inject-do-exports.mjs` bridges that gap as a post-build step — it esbuild-compiles both the DO source and the cron entry through a **single** synthetic virtual entry (deliberately one bundle, not two — two separate esbuild passes duplicated shared Drizzle/Valibot declarations at the top level and tripped wrangler's deploy-dry-run with `The symbol 'drizzle' has already been declared.`), renames the exported identifiers to avoid colliding with the re-export trailer, and appends the bundle + `export { QuizSession, scheduled }` to the adapter's emitted worker.

If you touch that script, read its header comment first. The constraints — deterministic identifier renames, single-bundle for dep dedupe, sentinel-guarded idempotent reruns — are load-bearing and non-obvious.

## WebSocket protocol (project)

JSON messages `{ type, payload }`.

**Server → Client**: `state`, `participant-joined`, `participant-left`, `question-started`, `answer-count-updated`, `reveal`, `ended`, `error`.

**Client → Server**: `join {nickname}`, `submit-answer {qIdx, choice}`, `reconnect {participantToken}`.

**Host → Server**: `host-start`, `host-advance`, `host-reveal`, `host-end`.

Group by **domain**, split by **concern** once a file grows past ~300 lines.

## Import Hygiene — MANDATORY

After EVERY file modification, review the import block and remove ALL unused imports (types, helpers, icons, namespace imports). Leftover imports are bugs.

## Best Practices

1. **Auth first, business second** — every protected handler checks `locals.user` before anything.
2. **Normalize email** — `.trim().toLowerCase()` before any DB lookup. `users.email` is `COLLATE NOCASE UNIQUE`, belt + suspenders.
3. **Small, named errors** — prefer `throwAppError('NOT_FOUND', 'Quiz not found')` over generic throws.
4. **Storage write-through** — DO mutations hit `ctx.storage` before any broadcast.
5. **Never trust the client** — participant tokens verify via constant-time HMAC.
6. **No obvious comments** — if the name + type convey the meaning, the comment is noise.
